# AutoSub 產生字幕流程

這份文件把參考影片與 whatSub 類似工具的工作流轉成 AutoSub 的本機版目標。第一階段重點是公司內部 1 到 2 人使用：使用者自己提供影片或音訊檔，AutoSub 在本機預覽、產生繁體中文字幕、編輯時間軸，最後匯出字幕檔。

## 第一階段流程

1. 使用者選擇本機影片或音訊檔。
2. AutoSub 在瀏覽器中載入媒體，建立可預覽的工作區。
3. 若是影片檔，本機 server 先用 ffmpeg 抽出低流量音訊。
4. 若是音訊檔，直接進入轉錄流程。
5. 本機 server 建立轉錄工作，並用 server-sent events 回報抽音訊、送 OpenAI、建立字幕與完成階段。
6. AutoSub 將音訊送到 OpenAI Audio Transcriptions API 產生文字與時間碼。
7. 轉錄結果轉成 AutoSub 字幕段落，進入播放器預覽與右側編輯器。
8. 使用者可逐段修正文字、時間、拆分、合併、新增字幕段、搜尋取代與品質檢查。
9. 完成後匯出 `.srt`、`.vtt` 或 `.txt`，也可匯出 `.autosub.json` 專案檔。

## 最小線上轉錄測試

正式測試 OpenAI 線上轉錄時，優先使用 10 秒音訊樣本，不直接拿完整影片測試。這個樣本只用來確認 API key、上傳、轉錄、字幕段落建立與播放器預覽是否串通。

```bash
npm run sample:audio
```

若要測影片預覽或剪輯流程，再使用 20 秒影片測試片。

## 參考影片與 whatSub 啟發的互動重點

- 產生字幕後要直接進入「影片預覽 + 字幕編輯」工作區，不做行銷式首頁。
- 進度要分階段顯示，讓使用者知道正在準備影片、抽音訊、上傳、辨識或建立字幕。
- 長影片或已有字幕時，產生字幕前要先提醒用量與覆蓋風險。
- 字幕要能跟播放器同步，點字幕時間可跳轉播放。
- 字幕文字與時間碼要能在同一個工作區快速修改。
- 拆分字幕要盡量接近參考影片體驗：快速、視覺提示清楚，不打斷文字編輯。
- 產出結果要能匯出標準字幕檔，方便放到其他剪輯或播放工具。

## 第一階段暫不做

- 不做登入、雲端保存、多人協作或付費方案。
- 不做由 AutoSub 直接解析 YouTube 網址；公司內部版先要求使用者提供自己有權使用的影片檔。
- 不做雙語學習、單字卡、收藏語料庫或 AI 解釋。
- 不把影片檔保存到 server；目前只在本機瀏覽器與本機 Node server 間流動。

## 後續候選

- 長影片分段轉錄與失敗續跑。
- 離線轉錄引擎，例如 whisper.cpp 或 faster-whisper。
- 雲端 / 離線轉錄模式切換。
- YouTube 網址匯入，但需要先確認授權、下載方式與公司政策。
